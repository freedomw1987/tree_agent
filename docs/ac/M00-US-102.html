類型 US ｜ 階段 ① 語音對話 loop ｜ 優先級 P0 ｜ SP 5
驗收方式：跑 `REGRESSION_MODULE=M00 ./run_pipeline.sh M00-US-102`

Given-When-Then

  1. Given 錄音鍵 When 按住講嘢再放開 Then 錄音期間見到 waveform / 計時，放開即時轉成可編輯文字（唔自動送出）
  2. Given STT 轉出空文字或「聽唔清」When 顯示 Then 保留輸入內容並提示重錄，唔會送出空訊息
  3. Given 一段 ≥ 60 秒錄音 When 達到上限 Then 自動停止並提示「太長，分段講」
  4. Given 輸入欄左邊嘅模式轉換鈕 When 由 Voice 切到鍵盤 Then 輸入區變成多行輸入框、右邊出現「傳送」鈕；切返 Voice 則變成通欄「按住 說話」鈕
  5. Given Voice 模式 When 按住「按住 說話」不放 Then 顯示錄音狀態（「放開發送」＋計時）；放開即完成錄音並傳送（唔使再撳傳送）
  6. Given 錄音完成但 STT 結果為空（聽唔清） When 放開按鈕 Then 唔會送出空訊息，提示重錄
  7. Given 麥克風權限被拒 When 首次錄音 Then 顯示權限說明 + 導去系統設定（唔會 crash）
  8. Given 錄音途中來電 / 藍牙耳機斷線 When 發生 Then 錄音安全中止，已錄內容保留並提示

Definition of Done

實測結論

UI 層已就緒：「按住 說話」掣（觸控開始／放開送出）、語音模式／鍵盤模式切換、STT 冇 plugin 時自動退回鍵盤（唔會卡死）。**未做**：native STT plugin（iOS SFSpeechRecognizer zh-HK / Android SpeechRecognizer）—— 要寫 Swift ＋ Kotlin ＋ Tauri plugin 骨架（M01 plugin 層，見 US-131）

業務規則

STT 一律 device native（音頻唔上傳）；語言 zh-HK；輸入模式：左側 Voice/鍵盤轉換鈕，Voice 模式按住「按住 說話」（放開即完成錄音並傳送），鍵盤模式多行輸入 ＋ 右側「傳送」鈕；『語音送出前先編輯』設定預設關（開啟則轉成文字先編輯再送出）；STT 空結果唔可以送出
