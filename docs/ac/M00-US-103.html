AC — M00-US-103

類型 US ｜ 階段 ① 語音對話 loop ｜ 優先級 P0 ｜ SP 8
驗收方式：跑 `REGRESSION_MODULE=M00 ./run_pipeline.sh M00-US-103`

Given-When-Then

  1. Given macOS App 啟動 When sidecar spawn Node/Bun process 並載入 `@earendil-works/pi-coding-agent` Then 建立 `createAgentSession()`（cwd = 用戶指定 workspace），App 顯示「Agent 已就緒」
  2. Given 一段 prompt When 經 IPC 交畀 sidecar Then 收到 streaming text delta 並即時轉發去 backend
  3. Given App 退出 / Mac 睡眠 When sidecar 收到 SIGTERM Then 正常 `session.dispose()`，唔留孤兒 process
  4. Given sidecar 崩潰 When supervisor 偵測到 Then 自動重啟（≤ 5 秒）並喺 App 顯示「Agent 已重啟」
  5. Given 用戶發一句新訊息 When Agent 判斷話題 Then 同一話題續返原本 session；新話題開新 session 並自動命名（用戶唔使理）
  6. Given 用戶想「帶住舊上文開新」 When 呼叫 fork 入口 Then 由現有 session 分岔出新 session，原本 session 唔受影響
  7. Given macOS App 閂咗 / Mac 進入睡眠 When sidecar 收到終止訊號 Then 正常 dispose（session 檔保留、唔留孤兒 process）；期間派落嘅任務留喺 SQS 隊列，下次啟動自動補做

Definition of Done

  • 探針 `M00-US-103-sidecar-session-lifecycle` 必通過
  • dispose 後 `ps` 檢查無殘留 process

實測結論

批次 1 已完成（Node/TS 層）：runtime/sidecar/ — session host（create/continue/open/list/fork/switch ＋ 自動分流 ＋ 自動命名 ＋ streaming chunk/done）、IPC 協議（stdio JSON lines，15 條探針）、崩潰 supervisor（自動重啟 ≤ 5 秒，實測 3 條探針）、真 Pi SDK factory（已實測開到 session：sessionFile → ~/.pi/agent/sessions/…jsonl，model MiniMax-M3.1-Flash，開 session 唔調模型）。**未做**：Tauri macOS 殼（App 顯示「Agent 已就緒」）、Workspace 選擇 UI、Relay(SQS) client 接線 → 對應 M01/M02 批次

業務規則

session 由 sidecar 用 file-backed SessionManager 持久化喺 Mac 本地（唔上傳雲端）；workspace 由用戶指定（預設 `~/agent-workspace`）；session 屬於一個 workspace（切 workspace = 換一組 session）；session 分流規則：同一話題續舊、新話題開新並自動命名；fork（帶上文開新）只係第二入口、預設唔開；**sidecar 生命週期 = 跟 macOS App 生死**（App 開住 = 醒住；App 閂咗 / Mac 瞓咗 = 停 → 任務留喺 SQS 隊列保留 ≥ 1 小時，下次啟動自動補做）

依賴

Pi SDK（Node ≥ 20 或 Bun）、Tauri sidecar 機制（`newSession` / `switchSession` / `fork`）
